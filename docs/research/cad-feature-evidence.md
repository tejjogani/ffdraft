# CAD feature evidence

**First audit · 26 November 2026 · `afcac8d`.** A jeweler can bring supported parts and curves into Pavé, edit selected dimensions, and take geometry back out. Opening a drawing does not reconstruct the original shank, stones, prongs and constraints as parametric jewelry features. Editing a mesh vertex and editing the original trimmed surface are different capabilities.

The original command inventories and the first audit remain dated. The coverage rows below incorporate subsequent changes documented under imported-model updates. The tables use the stable row IDs and command lists in [the Rhino inventory](22-rhino-full-parity.md#3-the-inventory-and-the-parity-matrix) and the job numbers in [the jewelry inventory](13-jewelry-cad-features.md#3-capability-matrix). **Available** describes the specific behavior named in a row. **Partial** identifies its limit. **Gap** means this audit found no product operation for that job. A row can contain several Rhino commands. No row establishes coverage of every command option. The original plan, kernel spikes and historical counts remain in the research documents.

## What to load from a jewelry model

Use each model to answer two questions. What can a jeweler do with it today? What information would make the next real edit possible? A whole-file geometry check answers whether the shapes survived. Also compare the original object's attributes, the project’s feature types and facts, and the attributes on the downloaded 3DM.

| Information in the source | What a designer can reuse today | What is worth loading or building next |
| --- | --- | --- |
| Measured solids, units and block placements | Open an assembly at its original size, measure it, select individual parts, copy exact edges or eligible face borders, and exchange native geometry. | Load the visible supported geometry and retain source IDs. Test each claimed editing tool separately. A pair of matching planar ends supports the measured cap move. A faceted body with different topology exercises another case. |
| Curves and profiles | Include editable curves when importing. Designers can move their NURBS control points and preserve their weights and knots on export. | Let the designer choose relevant guides. Linking an imported NURBS rail or profile to Pipe or Revolve still needs implementation. Prove it by editing the source curve and measuring the rebuilt feature. [Studio import](../../apps/studio/src/features/cad/model-import/ModelImport.tsx) · [Profile input types](../../packages/schema/src/design/nodes.ts) |
| Groups, block definitions and occurrence attributes | The editor retains source groups, member layer, placement layers and display material labels. A review can reuse a uniquely paired setting in another occurrence. | Editable shared block definitions and rebuilding literal nested block structure on export remain open. |
| Appearance, stone role and settings | Unassigned and reference parts remain available for viewing and exchange. Confirming a metal assigns a casting alloy. Confirming a stone creates a measured gemstone with its own sourcing target. A separately identified head retains its original shape until a refit or construction edit. | A procedural head can rebuild on refit. Independently selected handmade parts can instead retain their geometry and follow the confirmed stone’s measured frame. Each part can use an affine edit, or the designer can bend continuously across parts and exchange the nonlinear result as a mesh. Verify joint contact, wall thickness and clearances at the bench. [Role review](../../apps/studio/src/features/cad/rhino/RhinoRoleReview.tsx) · [Placement and measurement](../../apps/studio/src/features/cad/model-import/role-measurements.ts) |
| Geometry with sparse metadata | Similar face patterns and dimensions help a designer find related parts even when names and materials are absent. | Offer similar parts for review. Stone species, supplier, actual carat and the connection between a stone and its seat each need independent evidence. Keep unreferenced material-library entries and hidden presentation objects out of the project assistant's working context by default. |

The file comparison exposed a specific loss of design intent. One assembly used the same block on different occurrence layers with different render-material labels. Many groups shared a pattern of solids, guides and a placed block. The returned 3DM retained the solids, but all those block placements appeared on the member layer and the source groups and render-material table were absent. The second assembly contained unnamed solids with the same face and edge counts, closed curves, and no group or material records. Both imported projects reported zero stones and assigned the default metal to every body.

For the next acceptance case, start with a jeweler-identified stone, its host and one untouched neighboring setting. Ask the designer to confirm which selections belong together, replace one stone with a measured alternative, then check its seat clearance, neighboring geometry, stone count and metal-only casting output. A metadata-rich file tests whether the importer preserved the clues. An unlabeled file tests whether the designer can supply the missing relationship. For a workflow trace, record the selected parts, the requested change, the before-and-after measurements and the designer’s correction or acceptance. Record unsupported tasks even when the file passes the geometry round trip.

## Command names outside the original groups

The 26 November comparison of the official HTML `h5` headings found 1,078 Rhino 8 entries, **1,076 distinct displayed headings**. CopyDetailToViewport and ViewportProperties each appear twice. Rhino 9 has 1,123 distinct displayed headings. Case-sensitive comparison finds 66 headings unique to the Rhino 9 list, including renames and changes in spelling. A new heading does not necessarily represent a new operation. The matching Rhino 8 command names remain in the historical inventory. ### What working designers do

Gary Dawson documents a client’s size 5 bezel ring in Rhino. He draws the finger circle and the bezel guides, makes cross-sections for the shank, sweeps one side, mirrors the other, closes the solid and fits the bezel. This lets him revisit the band width and bezel height before printing. A finger circle establishes the inside diameter. The rail guides the band around the finger. Sections determine what the metal feels and looks like at the palm and shoulders. [Dawson’s illustrated commission](https://www.garydawsondesigns.com/blog--updates/previous/3) · [McNeel’s manufacturing demonstration with Dawson](https://www.rhino3d.com/kb/designing-jewelry-for-manufacturing/) · [Rhino Sweep2](https://docs.mcneel.com/rhino/8/help/en-us/commands/sweep2.htm)

For an interwoven pendant the designer recesses a surface, fills it with stones, refines the shared prongs and adds a loop and bail. ### Revision checks to build against

The first check runs over the public Python client against the app's geometry engine. On a disposable native halo the center was a 6.1 mm cushion, the band was US 6 and the piece had 31 stones. A synthetic inventory fit of 6.4 × 6.3 × 4.0 mm changed the production metal estimate from 2.8423 g to 2.8961 g. Resizing to US 7 produced 2.9934 g and kept all 31 stones in this fixture. Reopening preserved the center, halo, head and shoulder-row links. Undoing the finger-size edit returned to US 6 and 2.8961 g while retaining the replacement. These are computed weights and fixture dimensions. The test uses production-detail evaluation at each stage. [Repeatable revision test](../../packages/pave-python/tests/test_live.py) · [Studio sourcing test with fixture inventory](../../apps/studio/e2e/sourced-diamond.ts)

The following pieces cover different reasons a designer returns to Rhino. Each is a separate acceptance case. For every proposed tool, repeat the edit in Studio and through the project assistant, inspect the resulting geometry, and check undo, reopen and exchange in the receiving application.

1. **Custom solitaire and matching band.** Change the finger size and replace a measured oval. Measure the inside diameter, shoulder profiles, gallery-to-pavilion clearance and gap to the matching band. Keep the measured stone dimensions fixed when resizing the band.
2. **Shared-prong pavé ring.** Move one shoulder stone, lock a neighbor, change the row length and reopen. Retain their identities. Read back the stone positions, gaps, affected prong positions and cutter openings against the workshop’s targets.
3. **Iced logo pendant on a Cuban chain.** Fit different stock sizes into a bounded face, preserve empty lettering and stone edits, then pass the actual clasp dimensions through the bail in the model. Compare the measured casting STL with the approved CAD and try the clasp and hang on a sample.
4. **Returning Rhino customer.** Import the customer’s 3DM, establish which parts are guides, stones and metal, and revise one mounting. Compare scale, placements, unchanged neighbors and native or mesh output in Rhino. Ask the setter to review bearings, retained stock and access on the printed pattern.
5. **Matched stud earrings and a hinged bracelet.** For the earrings, verify independent projection, basket and post orientation on both sides and fit the supplied backs. For the bracelet, export the pin, hinge leaves and clasp separately, measure their clearances, and check motion from closed to the requested opening angle.

## Work to prioritize against real assemblies

1. **Account for everything at import and export.** On each original run locally, tally source geometry types, nested placements, visibility and skipped reasons. Track per-part units, poses, bounding boxes, closedness and returned types. Exercise repeated, mirrored, nonuniform and nested placements. Account for hidden layers, objects without cached meshes and unsupported objects explicitly. Compare against the source reader and an independent Rhino inspection where available.
2. **Make edits predictable on the original construction.** Build synthetic fixtures for an annular trimmed BRep with an inner loop, a solid with curved boundary edges, multiple placements of one definition, and a detached NURBS rail. For a cap edit, measure both radii, signed displacement and volume change, check every trim loop, and verify that moving one occurrence preserves its siblings. Reject unsupported face selections without changing the model. For a rail or mesh, edit one control point or one precisely identified component. Measure the change and untouched neighbors, including rational weights, knots, trim loops and orientation. Check cancel, stale edits, undo, save/reopen and export. Native cap moves meet the narrow through-bore case above. General trimmed-face editing still needs a separate test on a face outside that construction.
3. **Recover jewelry relationships with reviewable evidence.** Allow a designer to identify the shank, stones, rails and prongs, including ambiguous or repeated parts. Test a ring resize and a stone replacement preserving stipulated dimensions and symmetry. Measure seat clearance, prong contacts, neighboring stones, wall thickness, resulting shell count and alloy assignment. Treat a descriptive name as a hint until the geometry or designer confirms it.
4. **Run the same measured task through three entrances.** Exercise Studio controls with pointer and keyboard, Python over live HTTP and the assistant from a natural-language request. Check persisted feature IDs, version, geometry and exported representation independently on each route. Run scripted agent/tool integration and live-model task selection separately. Include an unsupported request, an ambiguous target and a stale-version retry.
5. **Build the next missing geometry operations from these cases.** Extend rail sweep coverage to periodic two-rail shanks, then address native topology selection, surface projection and trim/join/cap. Then test picked-edge blending and shelling on small features where failing geometry can still look right in a render. Add construction and continuity tests for advanced surfaces, SubD, remeshing and drafting. Cases should retain the expected error or omission when reconstruction is impossible.

Record the commit, fixture, operation, test command, environment, measured tolerances and resulting geometry type when upgrading a row. Keep private project files, names, derived coordinates and images out of checked-in fixtures. Use independently constructed examples to test functionality. A private local result may establish a workflow on those inputs, it cannot establish general feature parity.
