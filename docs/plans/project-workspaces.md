# Pavé project workspaces

A jeweler should be able to open a client's project, add a sketch or use a studio moodboard, edit the setting, and return later to the same work. Each tool opens directly on that project. A designer bringing finished CAD can begin in CAD or Render. A designer with a client's measurements can begin in Design.

This roadmap describes the integration branch at `0fd200d` (26 November 2026). “Available” below means a route or command exists at that revision. The first card treatment, read-first specification, signed-out Diaex RPCs and measured refitting have landed. The founder’s revised landing layout and Home-to-builder conversation below supersede the earlier vertical landing design. The [agent board](../agents/BOARD.md) tracks lane ownership. In particular, coordinate the CAD shell with A11/A13, spec changes with A7/A15, and modeling commands with B2.

## 1. Make the project an identifiable place to work

Use **Projects → folder → project → tool**. A folder may contain one further level of folders, as the collections service allows. Projects with no folder remain directly accessible in Projects. The project owns its brief, specification, design references, CAD, renders, shots, sourcing decisions and history. The studio owns the independent **Moodboards** library and its reusable brand models.

- [ ] Make folders useful at both entry points. At Projects, show folder names, children and contained projects. In the project switcher show the folder path alongside matching project names, especially when two clients have pieces named “Solitaire”. Preserve the current tool on switch. Clear old reference selections, shot selections and query parameters. Restore each project's own conversation draft when returning.
- [ ] Present project tools as compact, button-like cards, **two per row** at ordinary desktop and phone widths. Each has a recognizable name, a one-line description and one destination. Keep the artwork subordinate to the text and give each card room to wrap at large text settings. Preserve the **vertical tool list inside builders**. Show current CAD whenever geometry exists, and keep spending in the separate Project spending disclosure. Replace placeholder card descriptions as each tool becomes usable.
- [ ] Make the next action visible on entry to each tool. Design offers a reference, a note, or an imported moodboard. CAD offers a template, a blank piece, or a supported mesh. Render offers framing and a draft. On model shows the shot setup. Sourcing shows the stone or the missing prerequisite. Production can show existing packages and offer preparation when the engine is available. History shows who changed what and which edits can be undone.

**Acceptance.** Starting at Projects, enter a nested folder, open a piece, open each of its seven tools, switch to a second piece, refresh and go Back. Check project IDs, breadcrumbs, assistant context and retained drafts. Test at 390 px and 1440 px, with keyboard activation. Opening a page alone creates no boards, renders or assistant runs. Update the existing single-stack assertions to expect a two-column landing and a single vertical builder list. Extend the [project navigation walk](../../apps/studio/e2e/project-navigation.ts) and [card/specification walk](../../apps/studio/e2e/project-cards.ts). The [area registry](../../apps/studio/src/features/projects/areas.ts) owns destinations, including the existing `/directions` for Design and `/design` for CAD.

## 2. Separate studio Moodboards and project Design

**First visit.** Entering Design should immediately offer **Add a reference**, **Sketch**, **Write a note**, and **Import moodboard**. The first button opens the file chooser. A drop or paste works before a board exists. Canceling a picker leaves the project empty. Show **Grid** and **Canvas** once something can be arranged. On an existing board the same actions add to the visible board. The brief records the client's request. Keep a legible specification beside the Design work, with full labels for metal, finish, ring size, band width, band thickness, stone, cut, setting and quantities as applicable. Expose units at the values, unknowns explicitly, and existing edit, question and CAD-build affordances.

- [ ] Replace global **Ideas** with **Moodboards**. Give the library its own route and redirect old Ideas bookmarks. Resolve existing project-owned board bookmarks to the matching project Design and board. Add a library scope to `boards.list` that queries `pieceId IS NULL AND pinsFor IS NULL` in the current organization. Preserve the old list contract for other callers during migration. A project's new sketch, a pin board and a second client's Design each stay out of this library.
- [ ] Ship the first-item owner's proposed `references.saveForPiece({pieceId,items})` path for the first write and `references.save({boardId,items})` for an existing board. Resolve or create the project board and insert the first item atomically. A failed write, double click or two tabs must leave a consistent board. Teach the Design job to discover existing boards with a read before it creates one for a write.
- [ ] Add `boards.importMoodboard({sourceBoardId,pieceId,boardId?})`, where optional `boardId` selects a board already owned by that project. Without it resolve the project's design board. Copy the library board's references into the destination in source order, with notes, usable asset references, source/credit, rights and generation lineage preserved. Record source board and item IDs on the copies and deduplicate repeated imports by destination and source item. Commit in one transaction. Validate source library membership and destination ownership server-side. Existing projects or pin boards cannot be substituted as sources. Later source edits and project edits remain independent.
- [ ] Make imported material available to the assistant. The current turn builder includes a board title, explicitly supplied reference IDs and project pins. Resolve the active Design board on the server from the request's piece, carry the imported notes and source IDs into its context, and send only images permitted by the existing rights checks. For a large board show how many references were included, prioritize explicit selections, and let the assistant read additional permitted references on demand. Use the same selection in chat, the Design job and the image brief. An import is complete when the designer sees which material will inform the AI.

**Acceptance.** Create “Art Deco” with an owned sketch, a note and a view-only image. Import into projects A and B. Both see the three items, a retry adds zero duplicates, an edit in A leaves B and the library intact, and the library still lists only “Art Deco”. A scripted assistant turn names the note, cites the sketch, and receives only title/credit for the view-only image. Its outgoing media excludes the restricted pixels. Switch projects while an import finishes and check the results in the intended project. Cover the [board handlers](../../apps/server/src/handlers/ideate.ts), [turn builder](../../apps/server/src/assistant/turn.ts), [board surface](../../apps/studio/src/features/ideate/DesignBoard.tsx) and legacy routes.

## 3. Put AI where a designer has a question or a task

### Begin on Home with a client commission

Give a new Home conversation the full content area, with a quiet composer, attachments and the ongoing exchange. Keep the conversation in place through discovery, including after it creates a project. Carry the project ID, brief, attachments and selected concept into the builder when the designer chooses the handoff. A floating assistant can accompany the work inside the builder.

**Acceptance commission.** A designer drops a logo and asks for a pendant. Store the actual uploaded logo as a project reference and the request as the project brief, retaining both across reload. Ask whether they want a chain and which kind if their wording leaves it open. If they already asked for a Cuban chain, record that choice and skip that question. Invite a reference showing the intended look and clarify metal, stone sizes and other unresolved measurements. Propose several genuinely distinct concepts on that brief, with differences visible in silhouette, setting or logo treatment. Show the selection and carry its reference ID and agreed measurements forward. Start CAD only after the designer has selected the direction and chosen to build it. Invite feedback on the result and attach the requested revision to that project's history. A second conversation can begin with a finished CAD file and go directly to the requested tool. Test the logo path with a scripted assistant and fixture concepts, including the explicit-Cuban branch and returning from CAD to the same conversation.

### Work inside a project

| Entry point | Inputs the designer can inspect | Result |
| --- | --- | --- |
| **Ask about this project** on the project page | Piece, brief/spec, selection if present, previous project conversations | Open a scoped draft. Support asking “What still needs a measurement?” before starting any job. |
| **Explore designs** in Design | Current board, selected reference, imported context and brief | Offer the existing Design job or the image-brief path. Show reference rights, count and generation estimate before starting paid image work. Save resulting images to this Design. |
| **Build from this reference** or **Ask about this setting** | Selected reference or CAD node, piece version and spec | Show open dimensions and assumptions, estimate, then the CAD job or a previewed edit. An accepted spec amendment records the change. |
| **Plan shots** in Render | Current CAD, saved scenes and selected shot references | Show proposed angles, stills/animation, local machine time and allowance. Capture framing before rendering. A designer can edit a shot and resume. |

- [ ] Reuse the piece-scoped composer and `StartJob` for the three existing job stages. `threads.send` carries `context.pieceId`, board/scene/selection, reference IDs and a retry-stable `clientMessageId`. Keep the goal editable. Present **Check with me** and **Do it all** wherever the stage job can be started, using A11's agreed behavior when integrated. Both modes retain the server's spending limits, required approvals and person-only operations. Surface working, waiting, paused and ready-for-review states through the existing job panel. Opening an entry point or choosing a reference alone never submits.
- [ ] Home keeps its conversation full-screen until handoff. A project assistant opens the chosen piece immediately and can act on its Design, CAD and renders. Switching piece replaces the visible project context. A late reply stays attached to its originating thread. Where the assistant or image engine is unavailable, explain which capability is missing and keep manual upload, editing and CAD accessible.

**Acceptance.** With a scripted assistant, open the same goal from the project and the local tool, inspect identical scope, cancel freely, then start once. Change projects while the reply is pending and verify the result was stored on the first piece. Test editing during a running CAD job, resume against the newer version, accept a result, and inspect its history. Exercise Render with a saved camera and without Blender. Show a supported browser preview or the correct setup state. Start from the [stage job launcher](../../apps/studio/src/features/assistant/jobs/StartJob.tsx) and [own-CAD routing plan](own-cad-and-routing.md).

## 4. Make On model useful before generation is connected

The studio's Models, model detail and project On model screens are placeholders at the baseline. The server already supports synthetic model cards, approval, per-piece shot history, estimates, cancellation and checked export. Standard server composition registers no on-model service. A working image-generation key by itself will still yield an empty `session.get.capabilities.onModel`. [Model and shot handlers](../../apps/server/src/handlers/models.ts) · [Server composition](../../apps/server/src/compose.ts) · [Brand model design](brand-models-v2.md)

1. **Available without a provider.** Build model selection from `models.list`, an explicit synthetic attestation on `models.create`, model card edits, and a person-operated approval flow on `models.update`. Show `shots.list({pieceId})` even when generation is offline. Let designers prepare placement, framing direction, aspect and count. Surface missing CAD or model with a direct return path. Preserve choices while visiting the model library. Show existing shot status, findings and whether the model or piece has changed since it was made.
2. **Engine dependency.** Register the `OnModelService` adapter and advertise only supported capabilities. Its existing shot input accepts model ID, piece ID, hand/neck/ear/wrist, direction, aspect and count (1–4). It has no render ID input. The adapter must produce or retrieve calibrated reference views of the current CAD and approved model. Start with a ring on a hand and a known ring bore. Expand placements only after a size and orientation fixture passes for each. Keep actual measurements and provenance with the job.
3. **Generation.** When prerequisites hold, call `shots.estimate` and show the returned time and cost. Submit `shots.create` on explicit confirmation. Preserve shot IDs through reload and cancel with `shots.cancel`. Show the actual fidelity check, AI disclosure and source versions. Offer `shots.export` only with a passing check and an asset. Installed engines determine availability on the server as well as in the UI.

**Acceptance.** On an unconfigured installation, select the project and model, see earlier shots and read the unavailable reason with zero provider calls. With a deterministic fake adapter, reject a draft model, estimate without generating, cancel an active shot, and finish a separate shot. A changed piece marks the older shot stale. A failed check prevents export. The successful download belongs to this model and piece. Use a fixture adapter for this walk. Photographic quality and real-provider latency are later adapter acceptance work.

## 5. Source a real stone and fit one mount

| Dependency | Designer's action | Visible outcome |
| --- | --- | --- |
| Evaluated CAD | Select a gem or a lot | Show role, quantity, cut, drawn seat dimensions, tolerances and origin. A plain band has no stone requirement. A parcel remains a quantity/weight requirement. |
| Diaex search or exact listing access | Compare candidates, or paste a public ID/listing URL | Distinguish a successful empty result, inventory outage, missing measurements, unsupported material and unavailable stone. Offer a filtered browse link when available. |
| Individually addressable gem and available measured stone | Preview fit, then apply | Show length × width × depth, changes to the seat and linked setting, warnings and before/after facts. A successful choice creates one undoable change with the listing identity. |

The baseline includes [stone requirements](../../packages/sourcing/src/requirements.ts), a filtered Diaex link-out and measured `design.replaceStone`. The merged server exposes `sourcing.search({pieceId,nodeId,color?,sku?})` and `sourcing.stone({pieceId,nodeId,sku})` with server-configured `PAVE_DIAEX_PARTNER_API_URL`. The project Sourcing screen still needs to call them. The exact-ID lookup and partner search have separate upstream availability. Signed-out results show permitted listing data and dimensions. Preserve a null price. Recheck the chosen listing by exact ID immediately before apply, and repeat the preview if the fit data or piece version changed. Use the preview's base version and a stable change ID. Inventory lookup and fitting create no supplier order or hold. [Measured refit](../../apps/server/src/handlers/design.ts) · [Partner contract](../integrations/diaex-partner-api.md)

**Acceptance.** A three-stone ring with separately modeled sides accepts two distinct SKUs independently. A duplicate SKU, unsupported repeated or scaled instance, sold listing, changed dimensions and stale piece each have their own visible outcome. No failed choice changes CAD. Retrying a successful write creates one change, and Undo restores the earlier setting. Exercise matching, listing paste and upstream outage against deterministic partner responses.

## 6. Build Rhino-class jewelry CAD in demonstrable increments

Today a jeweler can open a template or supported mesh, change node parameters, evaluate a design, undo a change, and export supported formats. The existing CAD command palette offers views, display modes, edits and exports. A `pipe` or `revolve` kernel node is only part of a from-scratch Rhino-style workflow. The following commands are **planned**, and should become discoverable as their operations pass end to end. B2 owns model and kernel behavior. Keep the project shell independent of these milestones. [Freeform CAD steps 1–8](freeform-cad.md) · [Additions and parity ledger](freeform-cad-additions.md) · [Rhino capability inventory](../research/22-rhino-full-parity.md)

| Delivery | Commands and behavior to expose | A designer can demonstrate |
| --- | --- | --- |
| 1–2. Draw to a size | Persistent keyed curves, construction planes, End/Mid/Cen/Int snaps, typed coordinates, Curve/Polyline, Circle, Arc, PointsOn, Offset and the shared `design.run` verb registry | Start a blank US 6 ring, draw a symmetric profile, edit one point numerically, switch views, save and reopen with the same rail and dimensions. |
| 3–4. Make metal | ExtrudeCrv, Revolve, Pipe, Loft, Sweep1, union/difference, gumball Move/Rotate/Scale, Mirror, Orient and ArrayPolar. Attach settings to a drawn host. | Sweep a cathedral band from profiles, resize the rail, set a gem and mirror an accent. The bore tracks the size, the head follows and each gesture undoes once. |
| 5–8. Finish and transfer | Edge/face selection and `viewport.pick`, `design.inspect`, FilletEdge/ChamferEdge, Shell, section, trim/join, gem rows, pavé, engraving, Sweep2, Flow, measures, layers and STEP import | Select an actual model edge, preview a radius and see an actionable failure for an impossible fillet. Place a stone row on the drawn band. Reopen a STEP export externally and measure the band and seat. Clearly identify mesh bodies and partial .3dm transfer. |
| Jewelry workshop, then broader parity | Prioritize the additions plan's workshop sheet, target metal weight, stone pins/keep-outs, individual heads, matched bands and import grades. Stage open surfaces, trimmed .3dm solids, SubD, remesh and advanced fillets behind their geometry, licensing and interoperability gates. | Export a measured stone/metal sheet from the same model. Resize a ring while retaining locked stones and show wall/setting checks. Advance a capability's ledger state only after geometry and file read-back tests pass. |

Map Rhino aliases to the same typed tool definitions the assistant reads and runs. Capture the selected objects, numeric options, preview and one attributed history change through `design.apply`. Keep the last valid shape while solving and give an explicit reason when a command cannot operate on a selected object. Measure orbit, redraw and exact evaluation separately on representative hardware. For each capability, compare hand and scripted-agent results by measurements and topology. A palette match alone cannot establish parity. General surfaces, SubD-to-NURBS and joined .3dm solids need their own fixtures and independent read-back.

## Delivery order and review

1. **Try first:** project hierarchy, two-column project cards, a vertical tool list inside builders, first reference, independent Moodboards, and the full-screen Home commission through concept selection. Release when the two-project isolation and import tests pass in the browser.
2. **Complete a piece:** template or imported CAD, reference-to-CAD handoff, render framing and project history. Add the sourcing requirements and On model preparation screens in parallel. Run the actual workflows without paid calls, using recorded assistant interactions and a disposable instance.
3. **Enable external outcomes:** independently gate live inventory, checked on-model generation and production packages on their real dependencies. Use the documented fixture flows on every change. Enable a provider-dependent action on an installation only after a connected integration test succeeds.
4. **Expand the kernel independently:** implement B2's first eight steps and early workshop work in their documented order. The project remains usable between milestones. The first shop trial is a reproducible band, a measured setting and an external hand-off, with each result traceable to the project version.

For implementation PRs run the affected schema/server/kernel tests, the Studio typecheck and build, then the relevant Studio browser walks against a disposable server. Review a blank project, an existing piece with no board, a linked empty board, a populated board, and two same-named projects in different folders. Check success, cancellation, missing capabilities and a switch mid-request. Record which cases used fixtures and which used a connected deployment.
