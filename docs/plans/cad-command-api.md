# CAD commands for designers, Python and Claude

A designer should be able to adjust one prong in the inspector, ask Claude to make the same edit, or repeat it on a batch of projects from Python. All three paths must change the same geometry and produce an inspectable project history. Manual CAD runs locally without a model key. The existing render, export and assistant plan settings are separate.

## Release targets

Mac is the primary design and hands-on trial platform. Exercise each new CAD command in the Mac browser, from Python and through the project-scoped assistant. Windows x64 has a separate compatibility check for startup, CAD edits, Python and the managed render engine. Track Windows ARM64 separately.

## The command contract

1. Select a project and read `pieces.get`. Its design contains ordered feature IDs. Coordinates are millimetres, Z is up and angles are degrees. A ring's finger axis is Y.
2. Call `design.describe` with `pieceId` and `nodeId`. It returns the version, current values and the feature's input JSON Schema, including unit, range, default, applicability and reference metadata where provided. This comes from the schema used by the editor. Changing stone size or cut goes through the specialized `design.replaceStone` command so the mount can follow.
3. Write one intention as one `design.apply` with the version inspected, a readable label, a unique change ID and one or more operations. A merge patch changes only the named fields. If the document has moved, reread before deciding whether the old edit still makes sense. A retry of the same edit reuses its change ID.
4. Check `design.evaluate` for geometry facts and diagnostics. Inspect `design.history` for operations, inverse, sequence number and actor. Use `design.revert` to undo one sequence or one assistant run. Overlapping later changes can prevent a revert.
5. In the assistant's tool list these operations use underscores, for example `design_describe`. The CAD job and the project conversation dispatch them through the same server registry. A designer can work through the inspector without calling an assistant.

For a measured mesh, use `design.meshComponents` to read source-mesh vertices and triangles. An edge uses the two IDs of its endpoints. Use the returned version and source asset ID when applying sparse absolute vertex positions in source millimetres. For a NURBS curve, `design.describe` reads the degree, knots and weighted control points. A geometry edit can move one control point or adjust its weight in a single versioned change.

For a retained Rhino solid, `design.rhinoCapFaces` lists qualifying end faces. Pass the selected face index, returned native asset ID, project version and signed offset in millimetres to `design.offsetRhinoCap`. For an edge, page through `design.rhinoEdges`, request the exact curve for the chosen edge index, and add it with `design.apply` at the version inspected. The Python helpers expose both workflows. Re-read a selection after another edit changes its source or project version. [Face command](../../apps/server/src/handlers/rhino-caps.ts) · [Edge query](../../apps/server/src/handlers/rhino-edges.ts) · [Python examples](../../packages/pave-python/README.md)

The [Python package](../../packages/pave-python/README.md) contains callable examples. A script uses the permissions of its local session. Local scripts produce user edits. For an assistant tool call the server records the run ID and tool-call ID on the change.

A Studio model import can add up to 1,000 selected parts and curves as one change, with one Undo or Redo. The design API allows up to 500 operations in general edits. Larger requests must add measured parts and NURBS curves or remove nodes recorded by one such import. The Rhino reader accepts a 64 MiB file and up to one million triangles after expanding placed blocks. The browser regression crosses the former 500-operation boundary and checks atomic Undo/Redo and portable reopen. Larger selections can be split by layer. [Large-assembly browser test](../../apps/studio/e2e/large-model-import.ts) · [RPC boundary](../../apps/server/src/design.test.ts) The server’s 64 MiB command payload and the portable project archive’s size and asset limits also apply. A single STL imports as one triangulated part with the chosen units. [Rhino Mesh command](https://docs.mcneel.com/rhino/8/help/en-us/commands/mesh.htm) · [Rhino STL export](https://docs.mcneel.com/rhino/8mac/help/en-us/fileio/stereolithography_stl_import_export.htm)

A `.pave` carries editable curve definitions, mesh edits and retained native sources. Native retention for earlier mesh-only imports requires re-importing the original `.3dm`. Imported Rhino solids have native `.3dm` readback coverage. STEP parity for imported B-reps remains unverified.

## Local Rhino regression check

From an installed workspace, pass one or more local archives.

```bash
pnpm --silent cad:check-rhino "path/to/first.3dm" "path/to/second.3dm"
```

The check uses the production Rhino reader, design operations and kernel exporter with in-memory assets. It opens the original and exported archives directly through OpenNURBS and prints one JSON line per argument. Each line reports source units, layer and geometry counts, block usage, supported and skipped geometry, and the SHA-256 before and after processing. It exits nonzero if any archive fails a check or has too little supported geometry to exercise either editing path.

- Every imported curve is exported and reopened to check its degree, knots, parameter domain, weighted control points, layer, source ID and sampled positions. The check also compares unambiguous top-level curves to the source in millimetres, centimetres, metres, inches or feet. It edits one curve in memory and verifies the original and any probed neighbour after applying the inverse.
- The body probe picks one small solid preview, preferring a native part from a repeated block definition. When a disjoint neighbour is available, both are evaluated together. The check verifies the moved vertex in a mesh export, restoration after undo and the geometry of the untouched body. It reads native BReps and any exact affine instances directly from the export. Unsupported or absent geometry is visible in the report.

Both probes write exports in memory and use controlled selections for the edits. The [Studio import checks](../../apps/studio/e2e/model-import.ts) and [server archive tests](../../apps/server/src/pavefile/pavefile-engines.test.ts) exercise the browser workflow and persisted `.pave` exchange.

## Trace quality

Project history answers what changed, who changed it, and how to reverse it. An assistant run also has ordered tool inputs, results, errors, and a link to the resulting changes. A useful regression replays a request on a disposable project and verifies the observed shape, bounds, mass or other task-specific result. A tool returning success alone is insufficient. The project-scoping regression includes a refused cross-project read and ensures that the other project keeps its original version.

The organisation's evaluation-use setting defaults off. An opted-in organisation can export anonymised numeric before/after examples for band dimensions and individual prong tips from an explicitly chosen project. The exporter reconstructs each edit from its inverse and writes a local JSONL file. Designers can review ordinary history with evaluation use off. Training and shared dataset infrastructure are future work. [Evaluation example format and export guide](../cad-evaluation-examples.md)
